# The negative corpus — check.n's anchor

Sixty-six N programs, each wrong in exactly one way, each rejected by
`ncc` with one located, worded error. `MANIFEST.txt` records the
contract: for every file, the **exact first error line** ncc prints
(`file:line: message`), regenerated by running ncc over the corpus —
never written by hand.

This corpus is the differential anchor for **`check.n`**, the
self-host ladder's third module: where `lex.n` is held to
`ncc --tokens` and `parse.n` to `ncc --ast`, `check.n` must reproduce
these first-error lines — the location *and the wording* — for every
file it claims. A checker that rejects the right programs for the
right reasons, in the reference's own words, is checked in the
strongest sense available.

The corpus doubles as ncc's own regression battery (the verification
suite runs every file and asserts the message), so the two consumers
keep each other honest: a reworded ncc error shows up here as a
manifest diff before it can silently loosen check.n's target.
